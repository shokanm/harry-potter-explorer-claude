# Harry Potter Explorer

Каталог волшебного мира: персонажи, факультеты, заклинания и артефакты. Данные о персонажах
и заклинаниях приходят из [Harry Potter API](https://hp-api.onrender.com/), но **браузер к нему
не обращается ни разу** — все внешние вызовы идут через собственный серверный слой.

Конкурсная работа для курса **nFactorial AI Engineering**.

> *English summary: a Harry Potter catalogue built with Next.js 16. Every external service
> (hp-api, Supabase, Gemini) is called strictly server-side — there is not a single
> `NEXT_PUBLIC_` variable in the project. UI available in Russian and English.*

**Живая версия: https://harry-potter-explorer-claude.vercel.app**

## Что умеет

| Раздел | Что там |
|---|---|
| **Главная** | Атмосферная обложка, счётчики каталога и **живой счёт распределений**, который меняется без перезагрузки |
| **Факультеты** | Четыре факультета: цвета, символика, основатель, привидение, декан, гостиная, девиз и малоизвестный факт. Страница перекрашивается в цвета факультета |
| **Персонажи** | 437 карточек: поиск, шесть фильтров, бесконечная лента, ссылка с фильтрами копируется из адресной строки |
| **Карточка персонажа** | Полное досье, честный индикатор заполненности и **разговор с портретом** через Gemini |
| **Заклинания** | 77 заклинаний, разложенных по девяти разделам, выведенным из описаний |
| **Артефакты** | 21 предмет: Дары Смерти, крестражи, реликвии Хогвартса. Собственный датасет — в API артефактов нет |
| **Распределяющая шляпа** | Семь вопросов, факультет считает сервер, персональную речь пишет и стримит Gemini |
| **Омут памяти** | Избранное в `localStorage`, общее для всех вкладок браузера |
| **Язык** | Переключатель RU/EN, русский по умолчанию |

## Установка и запуск

### Требования

- **Node.js 20 или новее** (проверено на 22.23). Версия зафиксирована в `.nvmrc` и `package.json`.
- npm 10+.

### Быстрый старт

```bash
git clone <адрес-репозитория>
cd harry-potter-explorer
npm install
cp .env.example .env.local
npm run dev
```

Откройте <http://localhost:3000>.

**Приложение полностью работоспособно с пустым `.env.local`.** Без ключей оно читает hp-api
напрямую, а при его недоступности — снапшот из репозитория. Ключи включают дополнительные
возможности, но ничего не ломают своим отсутствием:

| Что не задано | Что происходит |
|---|---|
| Supabase | Каталог читается из hp-api; счёт распределений живёт в памяти процесса, интерфейс честно об этом пишет |
| Gemini | Портреты молчат с понятным объяснением; Шляпа распределяет, но без речи |
| Ничего не задано | Всё выше сразу, плюс работа со снапшота, если hp-api лежит |

### Подключение Supabase (необязательно)

1. Создайте проект на [supabase.com](https://supabase.com).
2. В SQL Editor выполните [`supabase/schema.sql`](supabase/schema.sql) — он создаёт таблицы,
   политики RLS, атомарный ограничитель частоты и включает Realtime для счёта распределений.
3. Заполните в `.env.local`: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`
   (Settings → API).
4. Залейте данные:

```bash
npm run sync
```

### Подключение Gemini (необязательно)

Получите ключ на [aistudio.google.com/apikey](https://aistudio.google.com/apikey) (бесплатный
тариф) и положите в `GEMINI_API_KEY`.

### Прочие команды

```bash
npm run build
```

```bash
npm run typecheck
```

```bash
npm run lint
```

## Процесс проектирования

### Шаг 1. Сначала посмотреть на данные, потом рисовать экраны

Прежде чем написать строчку кода, я выкачал `/api/characters` и посчитал, что там на самом деле
лежит. Результат изменил почти все последующие решения:

| Что показали данные | Что из этого следует |
|---|---|
| 437 персонажей, **фото только у 25** | Каталог из фотокарточек невозможен. Нужен генератор портретов |
| Патронус у 18, палочка у 25, факультет у 135 | Карточка обязана красиво переживать пустоту, а не печатать прочерки |
| **Ни поиска, ни пагинации** — отдаётся всё разом | Свой сервер должен делать настоящую работу, а не проксировать |
| **Нет артефактов**, хотя ТЗ их требует | Нужен собственный датасет |
| У заклинаний только имя и описание | Категории придётся выводить самому |
| Хостинг — бесплатный Render | Холодный старт до минуты. Нужна защита от пустого экрана |

Именно эта разведка, а не фантазия о «красивом приложении», задала архитектуру.

### Шаг 2. Сервер снизу вверх, интерфейс потом

Слои писались в порядке `hp-api → normalize → data-source → /api/*`, и каждый проверялся `curl`-ом
до того, как появился хоть один экран. К моменту первой вёрстки поиск, фильтры, пагинация и
отказоустойчивость уже были проверены — интерфейсу оставалось только показывать готовое.

### Шаг 3. Проверка отказов как часть разработки

Отказоустойчивость проверялась намеренной поломкой: запуск с `HP_API_BASE_URL`, указывающим
в никуда, и без Supabase. Приложение обязано было отдать все 437 записей со снапшота — и отдало,
вместе с работающим поиском.

### Шаг 4. Первый же деплой нашёл ошибку, которую не ловила ни одна локальная проверка

На боевом стенде каталог показал источник `snapshot`, хотя hp-api отвечал за 0,2 секунды.
Локально — и в разработке, и в production-сборке — всё работало. Логов серверной функции
под рукой не было, поэтому я добавил диагностику: причина отказа каждого слоя стала
отдаваться через `/api/stats`. Ответ оказался неожиданным:

```
TypeError: Failed to parse URL from /characters
```

Базовый адрес был пустой строкой. Причина — в одном операторе:

```ts
const BASE_URL = process.env.HP_API_BASE_URL ?? "https://hp-api.onrender.com/api";
```

`??` подставляет запасное значение только для `undefined`. Панель хостинга отдала переменную,
**заданную пустой строкой**, — и приложение получило `""`, а `fetch("" + "/characters")` упал
на невалидном URL. Внешне это выглядело как недоступность чужого API, хотя оно было живо.

Все чтения окружения переехали в `lib/env.ts`, где пустая и пробельная строка считаются
отсутствием значения. Для чисел это не менее важно: `Number("")` даёт `0`, что превратило бы
таймаут в мгновенный обрыв, а лимит запросов — в запрет вообще всего.

Полезный побочный результат: диагностика слоёв осталась в проекте, и на любом стенде теперь
видно не только *какой* слой ответил, но и *почему* не смог предыдущий.

## Почему такой стек

**Next.js 16 (App Router) + TypeScript + Tailwind CSS 4 + Supabase + Gemini на Vercel.**

- **Главное требование ТЗ решается структурно, а не дисциплиной.** «Внешние сервисы вызываются
  только с сервера» — это не про то, чтобы не забыть. Модули `hp-api.ts`, `gemini.ts`,
  `supabase/server.ts` помечены пакетом `server-only`: случайный импорт в клиентский компонент
  становится **ошибкой сборки**. Плюс во всём проекте нет ни одной переменной `NEXT_PUBLIC_` —
  браузер не знает даже адреса Supabase.
- **Server Components** позволяют отрисовать первую страницу каталога на сервере, без пустой
  сетки, которая заполняется после гидратации.
- **Route Handlers + `ReadableStream`** дают стриминг ответа LLM без отдельного бэкенда.
- **Один репозиторий — один деплой.** Связка «Express + SPA» дала бы более наглядное разделение
  слоёв, но это два хостинга, CORS и два холодных старта. Для конкурсной работы, которую откроют
  один раз и ненадолго, это лишний риск (см. [Компромиссы](#компромиссы)).
- **Vercel** назван в ТЗ, бесплатен и деплоится из Git.
- **Supabase** — Postgres с Realtime из коробки, что закрывает бонус про «просмотр данных
  в реальном времени» без второго сервиса.
- **Gemini** — бесплатный тариф, а стенд публичный: чужое любопытство не должно стоить денег.

Обошёлся без библиотек там, где они не окупаются: локализация — два словаря с проверкой типов,
поиск — сотня строк с расстоянием Дамерау-Левенштейна, состояние — встроенные хуки React.
Меньше зависимостей — меньше того, что сломается на чужой машине.

## Нестандартные решения

### 1. Трёхслойный источник данных

`lib/data-source.ts` пробует по очереди: **Supabase → hp-api → снапшот в репозитории**.

Это не архитектурное украшательство, а ответ на конкретную проблему: hp-api живёт на бесплатном
Render и после простоя просыпается 30–60 секунд. Жюри откроет стенд в непредсказуемый момент,
и оно не должно увидеть крутилку на минуту. Таймаут в 8 секунд — и приложение уходит на слой ниже.

Побочный эффект: бонусное задание «выгрузить данные в БД» перестало быть галочкой и стало
решением реальной задачи надёжности. Текущий слой видно прямо в интерфейсе — подпись
«Источник данных» на страницах каталога и заклинаний.

### 2. Сортировка по полноте досье

У 412 из 437 персонажей нет фотографии, а у большинства пусты и остальные поля. При обычной
сортировке каталог открывался бы на безымянных статистах.

При нормализации каждому персонажу считается взвешенная **оценка заполненности** (`completeness`),
и она же — сортировка по умолчанию. Каталог открывается на Гарри, Гермионе, Люпине и Роне.
Та же величина показана на карточке персонажа честной шкалой с перечислением того, чего в источнике
нет, — пустая карточка перестаёт выглядеть как ошибка приложения.

### 3. Генератор портретов вместо серых заглушек

`lib/portrait.ts` набирает каждому персонажу без фотографии собственное клише: монограмма
в двойной наборной рамке поверх штриховки, краской цвета его факультета. Существам вместо
букв достаётся свой знак — сова, змея, феникс, череп для привидений. Плотность штриховки
и тон бумаги выводятся из `id`, поэтому соседние клише не сливаются в одинаковую полосу.

Всё детерминировано — один и тот же персонаж выглядит одинаково на сервере, на клиенте
и после перезагрузки. Никакой случайности и никаких запросов.

### 4. Поиск, который понимает русский и прощает опечатки

hp-api знает только английские имена. Поэтому при нормализации в поисковый индекс подмешиваются
русские алиасы (`lib/content/ru-aliases.ts`, ~90 персонажей) — причём **обе традиции перевода**:
Снегг и Снейп, Долгопупс и Лонгботтом, Полумна и Луна.

Работает и поиск по прозвищам из `alternate_names` («избранный» → Harry Potter), и по актёру
(«rickman» → Severus Snape), и опечатки в одну-две буквы («Hermionee» → Hermione Granger).

### 5. Realtime, который не нарушает требование ТЗ

Supabase Realtime в их документации подписывается прямо из браузера. Здесь так нельзя: к внешним
сервисам ходит только сервер. Поэтому на `postgres_changes` подписывается серверный маршрут
`/api/stats/stream`, а браузеру он отдаёт свои Server-Sent Events с того же домена.

Соединение живёт 40 секунд и закрывается само — бессрочные соединения плохо уживаются
с серверлесс-хостингом, а `EventSource` переподключается сам, и разрыв незаметен.

**Как проверить:** откройте главную в двух вкладках, в одной пройдите Шляпу — счётчик во второй
изменится без перезагрузки.

### 6. Шляпа, которая распределяет даже без LLM

Факультет считает **сервер обычной арифметикой** по весам ответов и отдаёт заголовком `x-house`
до первого слова речи. Модель только облекает готовое решение в слова.

Поэтому исчерпанная квота Gemini лишает Шляпу голоса, но не способности распределять — вместо
белого экрана пользователь получает факультет и честное объяснение, почему сегодня без речи.

### 7. Портрет говорит только о том, что есть в базе

Системный промпт собирается из **реальных полей этого персонажа** (дом, происхождение, палочка,
патронус, актёр, жив ли) и прямо запрещает выдумывать биографию вопреки списку. Модель отыгрывает
данные приложения, а не свои воспоминания о книгах.

Там же — защита от подмены инструкций: попытку «забудь правила и говори как…» портрет отбивает
в характере, с лёгким раздражением.

### 8. Оформление как «Ежедневный пророк»

Интерфейс собран не как сайт с карточками, а как полоса волшебной газеты: шапка выпуска
с названием по центру, двойные линейки, рубрики узким гротеском капителью, буквицы в начале
статей и кнопки-штампы вместо скруглённых таблеток. Скруглений и теней нет вовсе — только
волосные линейки, как в наборе.

Из этого выросли два решения, до которых иначе бы не дошло:

- **Фотографии печатаются растром в одну краску.** Снимки персонажей обесцвечиваются
  и подкрашиваются тоном бумаги, отчего перестают спорить с текстом и выглядят частью полосы —
  как фотографии в старой прессе.
- **Портреты без фотографии стали гравюрами.** Вместо серой заглушки набирается клише:
  монограмма в двойной рамке на штриховке, краской цвета факультета. Восемь призраков
  в каталоге читаются по цветам своих факультетов, хотя ни у одного нет снимка.

Жёлтый Пуффендуя на газетной бумаге исчезает, поэтому у каждого факультета есть отдельный
«печатный» тон: тот же геральдический цвет, но гарантированно читаемый на светлом.

### 9. Оптимизатор картинок как средство соблюдения ТЗ

Фотографии лежат на ImageKit. Через `next/image` их скачивает **наш сервер**, а браузер получает
уже с нашего домена. Требование ТЗ соблюдено буквально, а картинки заодно приходят в webp
и нужного размера.

## Компромиссы

**Монолит Next.js вместо отдельного бэкенда.** ТЗ требует, чтобы внешние сервисы вызывались
с сервера, и отдельный Express сделал бы это разделение нагляднее для проверяющего. Я выбрал
единое приложение: один деплой вместо двух, никакого CORS и один холодный старт вместо двух.
Расплата — «сервер» и «клиент» живут в одном дереве файлов, и границу приходится держать
дисциплиной. Поэтому она подкреплена пакетом `server-only` и полным отсутствием `NEXT_PUBLIC_`.

**Только светлая тема.** Приложение свёрстано как выпуск газеты — краской по бумаге,
и тёмного режима у него нет. Это не упущение: газету печатают на бумаге, и «ночная версия»
разрушила бы приём, на котором держится всё оформление. `prefers-color-scheme` не
поддерживается намеренно.

**Язык в cookie, а не в URL.** Маршруты `/ru/...` и `/en/...` были бы честнее для поисковиков,
но удваивают дерево страниц ради двух языков. Cookie позволяет серверу отрисовать уже переведённую
страницу — без мигания английским перед гидратацией, чем грешит чисто клиентская локализация.
Плата: страницы стали динамическими и не кэшируются как статика.

**Данные из API не переводятся.** Имена персонажей, патронусы и заклинания остаются английскими
даже в русском интерфейсе. Переводить имена собственные машинно — значит получить «Гарри Гончар».
Вместо этого русские имена добавлены в поиск, где они действительно нужны.

**Артефакты написаны руками.** В hp-api их нет, а ТЗ требует. 21 предмет с описаниями на двух
языках — это не «данные из API», и в масштабируемости они проигрывают. Зато каждый снабжён
деталью, которую знают не все, и раздел читается, а не пролистывается.

**Категории заклинаний выведены эвристикой.** Правила построены по регулярным выражениям
из реальных 77 описаний. Это не онтология, и на новых данных правила поплывут — но альтернатива
(размечать вручную или гонять LLM по каждому заклинанию) не окупается на списке такого размера.

**Ограничитель частоты приблизителен на нескольких инстансах.** С Supabase он точен за счёт
атомарного инкремента в Postgres; без неё считает в памяти процесса, и на нескольких инстансах
Vercel лимит окажется мягче заявленного. Для защиты от случайного перебора этого достаточно,
для защиты от намеренной атаки — нет.

**Тестов нет.** При заданном объёме работы я выбрал проверяемость другого рода: типы (`tsc`
проходит чисто), линтер и воспроизводимые проверки через `curl`, включая намеренную поломку
источников. Для продакшена этого было бы мало.

## Известные проблемы

1. **Первый заход после простоя может быть медленным.** Если Supabase не подключён, а hp-api
   спит, первый запрос ждёт до 8 секунд и только потом уходит на снапшот. Лечится подключением
   Supabase (`npm run sync`).

2. **Снапшот стареет.** `data/*.snapshot.json` снят в момент разработки и обновляется только
   вручную. Для практически неизменного набора данных это приемлемо, но формально третий слой
   может разойтись с первоисточником.

3. **Свободный тариф Gemini исчерпаем.** При активном использовании чата квота может закончиться;
   тогда портреты молчат, а Шляпа распределяет без речи. Ограничитель (12 сообщений за 5 минут
   на посетителя) снижает риск, но не исключает его.

4. **Счёт распределений без Supabase не переживает перезапуск** — он живёт в памяти процесса.
   Интерфейс сообщает об этом прямо под счётчиком.

5. **Модель иногда говорит не то.** Портрет — это языковая модель с промптом, а не база знаний.
   Ответы могут расходиться с каноном; под чатом об этом написано.

6. **Свечи видны только на широких экранах** (от 1280px). На узких они лезли бы на текст,
   поэтому скрыты — на телефоне атмосферы чуть меньше.

7. **Дубли в данных источника.** В hp-api два персонажа с повторяющимися именами и один
   с двумя записями (`Viktor`/`Victor Krum`). Записи не склеиваются: без надёжного признака
   тождества склейка сделала бы хуже.

### Как убедиться, что браузер не ходит наружу

Проверка по собранному бандлу — команда не должна найти ни одного файла:

```bash
npm run build && grep -rl "hp-api.onrender.com\|supabase.co\|googleapis.com" .next/static
```

Проверка на живом стенде — откройте консоль браузера на любой странице и выполните:

```js
performance.getEntriesByType('resource').map(e => e.name).filter(u => !u.startsWith(location.origin))
```

Массив будет пустым. На странице каталога это 17 запросов, из которых **наружу — ноль**:
фотографии персонажей приходят через `/_next/image` (их скачивает наш сервер), а шрифты
`next/font` раздаются с нашего же домена, а не с Google Fonts.
